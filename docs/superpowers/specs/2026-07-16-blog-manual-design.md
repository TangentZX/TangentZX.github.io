# 博客操作手册设计

## 目标

在仓库根目录提供一份 `BLOG_MANUAL.md`，供博客维护者长期查阅。手册必须以当前 MkDocs Material 项目的真实结构、自动生成规则和 GitHub 发布流程为准，并提供可以直接复制使用的模板与命令。

手册属于仓库维护文档，不加入 MkDocs 顶部导航，也不作为博客公开页面构建。

## 面向场景

手册按维护任务而非源码模块组织，覆盖以下场景：

1. 启动、访问和停止本地服务。
2. 在校内篇、CTF 篇和杂篇中新建文章。
3. 设置作者、日期、嵌套分类和标签。
4. 存放并引用文章图片。
5. 修改首页、关于、友链和篇章简介。
6. 使用项目支持的 Markdown 扩展语法。
7. 定位文章、导航、友链、分类和目录跟随样式。
8. 严格构建、运行测试、提交和发布。
9. 通过本地代理执行 GitHub 推送。
10. 理解新旧博客分支及执行回滚。
11. 新增一个类似“校内篇”的完整篇章。

## 内容结构

正式手册依次包含：

- 项目概览和关键目录；
- 不应手动修改的自动生成内容；
- 本地开发流程；
- 三类文章的 front matter 模板；
- 分类、标签、排序和作者规则；
- 图片目录与 Markdown 引用规范；
- 固定页面和篇章简介修改方法；
- 代码块、行内代码、引用、表格、高亮、删除线、提示块、折叠块与公式示例；
- CSS 与 JavaScript 文件职责；
- 新建完整篇章的配置步骤；
- 构建、测试、Git 提交与 GitHub 发布；
- 旧 Hexo 博客的备份与恢复；
- 常见问题和发布检查清单。

## 新建完整篇章指导

以“阅读篇”为示例，指导维护者完成以下一致性修改：

1. 创建 `docs/reading/index.md` 和直接位于该目录下的文章文件；
2. 在 `docs/.nav.yml` 中加入顶部导航；
3. 在 `hooks/taxonomy.py` 的 `SECTION_TITLES` 中登记目录名和篇章显示名；
4. 在 `SECTION_CATEGORY_ROOTS` 中登记 front matter 分类根节点；
5. 使用 `categories: [[阅读, 子分类]]` 形成嵌套分类；
6. 运行 Hook，生成该篇章 `.nav.yml`、首页分类树以及全站分类与标签内容；
7. 为文章收集、导航生成和站点构建补充测试；
8. 执行严格构建、本地浏览和发布检查。

手册必须强调：篇章目录名、两个 Hook 映射和文章分类根节点必须保持一致；文章 Markdown 当前必须直接放在篇章目录下，因为收集逻辑只扫描 `*.md`。

## GitHub 与回滚

手册记录当前远程分支职责：

- `main`：新 MkDocs 博客源码；
- `gh-pages`：自动生成的网站；
- `legacy-hexo-source`：旧 Hexo 源码备份；
- `legacy-hexo-site`：旧 Hexo 静态网站备份。

正常发布不得手动编辑 `gh-pages`。回滚章节提供先核对分支、再恢复发布源的安全思路，避免把强制推送写成日常命令。

## 安全与验证

- 不修改现有 `docs/index.md` 或把其未提交改动纳入手册提交。
- 不建议编辑 `site/`、篇章 `.nav.yml`、归档分类页或标签页的自动生成区域。
- 所有命令以 Windows PowerShell 和 `D:\Project\new-blog` 为基准。
- 完成后检查 Markdown 结构、文件路径、front matter 示例和命令是否与项目一致。
- 运行现有测试和严格构建，确认新增维护文档不影响站点。
