# 全站文章阅读体验增强设计

## 目标

为所有现有和未来的 Markdown 文章提供统一的代码块、行内代码、表格和引用块样式，并修复长文章右侧大纲超过视口后无法持续跟随当前阅读标题的问题。作者仍只需书写标准 Markdown，不需要为单篇文章配置 CSS 或脚本。

## 实现方式

采用 Material 原生增强方案，不覆盖主题模板：

- 新增 `docs/resources/css/article-content.css`，所有规则限定在 `.md-typeset` 或右侧大纲容器内。
- 新增 `docs/resources/js/toc-follow.js`，监听 Material 更新的当前大纲链接，将超出可视区域的高亮项滚动到右侧大纲视口内。
- 在 `mkdocs.yml` 的 `extra_css` 和 `extra_javascript` 中全站加载这两个资源。
- 保留 Material 自带代码复制按钮、语法高亮、响应式导航和 Instant Navigation 生命周期。

## 代码样式

行内代码与代码块使用不同的视觉层级：

- 行内代码使用淡 Indigo 背景、较小圆角和适度内边距，不改变文本换行逻辑。
- 代码块增加统一圆角、细边框和阴影，并保持横向滚动，避免长代码撑宽正文。
- 代码块复制按钮继续使用 Material 原生实现，不重新绑定点击事件。
- 深色模式使用 One Dark 风格的背景和边框，浅色模式保持低对比度背景。

## 表格样式

- Markdown 表格保留语义化 `<table>` 结构。
- 表头使用 Indigo 淡色背景和更清晰的字重。
- 单元格增加边框与间距，偶数行使用轻微斑马纹。
- 表格宽度超过正文时由 Material 的表格容器横向滚动，不造成页面级横向溢出。
- 深色模式使用透明浅色边框和低亮度条纹。

## 引用块样式

- 引用块使用 Indigo 左边框、淡色背景、圆角和适度内边距。
- 保留嵌套 Markdown、列表、代码和段落的正常排版。
- 引用块首尾段落不产生额外空白。
- 深色模式改用蓝色强调边框与深色半透明背景。

## 右侧大纲滚动与跟随

桌面端右侧大纲的滚动容器限制在当前视口高度内，并设置独立纵向滚动。正文页面继续正常滚动，右侧大纲不会把整页宽度或高度撑开。

`toc-follow.js` 在页面初始化和 Material 页面切换后：

1. 找到 `.md-sidebar--secondary .md-sidebar__scrollwrap`。
2. 监听其子树中大纲链接的 `class` 变化。
3. 当 `.md-nav__link--active` 更新时，通过 `scrollIntoView({ block: "nearest" })` 仅在必要时滚动右侧大纲。
4. 监听页面哈希变化，确保直接点击标题和浏览器前进后退也能跟随。
5. 页面切换时断开旧观察器，避免重复监听。

移动端不启用独立右侧大纲规则，因为 Material 会将目录放入移动导航结构。

## 验证

自动检查包括：

- 新 CSS 和 JS 已在 `mkdocs.yml` 注册且文件存在。
- CSS 包含代码、表格、引用块、深色模式和右侧大纲滚动选择器。
- JS 包含 Material 页面生命周期、`MutationObserver`、活动链接与最近位置滚动标记。
- `mkdocs build --strict` 成功，现有迁移测试全部通过。

浏览器检查包括：

- 打开包含大量代码和图片的 `程序设计(A)(C)作业`，确认代码块不撑宽页面。
- 检查至少一个表格和引用块在浅色、深色模式下的可读性。
- 在长文章中滚动到后半段，确认右侧大纲可独立滚动且当前标题保持可见。
- 在 390px 手机宽度下确认无页面级横向溢出。
- 控制台无站点脚本错误。

## 非目标

- 不为单篇文章创建专属样式。
- 不修改迁移文章的正文内容。
- 不覆盖 Material 的 HTML 模板。
- 不新增代码执行、表格排序或大纲搜索功能。
- 不部署或推送 GitHub。
